# Setup and reproduction

This reproduces the base vs medical comparison in the paper: Gemma-3-4B vs MedGemma-4B
on VQA-RAD, 250 test samples (discovery 0000-0099, confirmation 0100-0249).

## 0. Requirements
- Python 3.10 or newer. The Kaggle runs used Python 3.13 with torch 2.11.0+cu128.
- A Hugging Face account. Both models are gated, so accept each licence on its page first:
  - https://huggingface.co/google/gemma-3-4b-it
  - https://huggingface.co/google/medgemma-4b-it
- Then log in: `huggingface-cli login`
- A GPU with about 16 GB of memory. One 4B model in bfloat16 takes about 14.4 GB, so
  load one model at a time. The paper runs used Kaggle T4 GPUs.

## 1. Install
```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```
`requirements.txt` pins `transformers>=4.50,<5`. Gemma 3 and MedGemma need 4.50 or
later, and transformers 5.x dropped the HQQ int4 path.

## 2. Settings used in the paper
- Precision: bfloat16, no weight quantization (`--dtype bfloat16 --quantization none`).
- Knockout window: `--k 1`, all 34 decoder layers, both block types
  (`--block_types image_to_last,question_to_last`).
- Generation: greedy, `--max_new_tokens 64`.
- Data: VQA-RAD test split, indices 0000-0249. Accuracy is on closed yes/no questions only.

Do not use `--quantization int4` with these models. It crashes with
`IndexError: index N out of bounds` (an HQQ-int4 bug with the Gemma 3 attention mask).

## 3. Run the tracing
Run each model with identical settings and output folders. The paper's runs were sharded
across two GPUs and merged. Shard boundaries are in `kaggle/`.

```bash
# base model, discovery split
python run_tracing.py --task vqa_rad --checkpoint_dir google/gemma-3-4b-it \
  --dtype bfloat16 --device cuda --quantization none \
  --start_index 0 --limit 100 --k 1 --max_new_tokens 64 \
  --block_types image_to_last,question_to_last --answer_path outputs_gemma

# medical model, discovery split
python run_tracing.py --task vqa_rad --checkpoint_dir google/medgemma-4b-it \
  --dtype bfloat16 --device cuda --quantization none \
  --start_index 0 --limit 100 --k 1 --max_new_tokens 64 \
  --block_types image_to_last,question_to_last --answer_path outputs_medgemma
```

For the confirmation split, use `--start_index 100 --limit 150`. Merge shards with
`merge_outputs.py`.

## 4. Accuracy re-evaluation
Accuracy uses the closed-question logit verdict. Re-run it with `reeval_accuracy.py`,
and pass `--old_fixed` and `--new_fixed` explicitly. Without them the script writes into
the discovery output folders.

## 5. Statistics and figures
```bash
python compare_models.py --old outputs_gemma_full --new outputs_medgemma_full \
  --output_dir figures_compare
```
This writes `metrics_summary.json` and the per-layer comparison figures. The statistical
tests and Holm correction are in `analysis/`. The paper figures are generated by the
scripts in `analysis/`.

## 6. Notes
- Each image takes about `num_layers` forward passes per block type. On a T4 this is
  seconds per sample. On CPU it is minutes, so a GPU is strongly recommended.
- Large outputs (`outputs_*/`) are git-ignored. Keep them outside the repo or share them
  as archives.
